# R-202 提交审核、撤回与驳回（REQ-004、REQ-005）

## 行为实例

| # | 操作 | 预期 |
|---|---|---|
| 1 | 没有图片就提交 | 拒绝，提示"至少上传一张图片" |
| 2 | 有图片提交 | 变待审核，开出一条待审流水 |
| 3 | 待审核期间再次提交 | 幂等，不新增第二条流水 |
| 4 | 审核通过（普通商品） | 变已发布 |
| 5 | 审核通过（勾了预售） | 变已预售，不是已发布 |
| 6 | 驳回但不写理由 | 拒绝，状态不变 |
| 7 | 驳回并写理由 | 变已驳回，流水补上结论 |
| 8 | 驳回后改稿重提 | 改稿回草稿→重提，流水累计两条，旧记录保留 |
| 9 | 审核自己发布的商品 | 拒绝（REQ-002 自审排除） |
| 10 | 商品已不在待审核时审核 | 拒绝，提示状态已变更 |
| 11 | 卖家撤回待审提交 | 回草稿，该条流水记 `withdrawn_at`，不再算待审 |
| 12 | 撤回→重提→审核通过 | 全程只留 1 条待审流水，其余是已关闭记录 |
| 13 | 内容被改坏（例如价格 ≤ 0）后审核通过 | 拒绝通过，记 denied 日志（审核前复查内容） |
| 14 | 待审期间卖家自己下架 | 拒绝（状态图二：待审核不在卖家可下架范围） |

## 契约

- `submit_for_audit(product, *, actor) -> Product`
- `audit(product, *, auditor, approve, reason="") -> Product`
- `back_to_draft(product, *, actor) -> Product`：撤回；来自待审核时关闭当前流水
- 流水在提交时开、审核时补结论、撤回时置 `withdrawn_at`：
  `AuditRecord(product, submitted_version, created_at, auditor, approve, reason, audited_at, withdrawn_at)`
- "待审"的判据是 `approve IS NULL AND withdrawn_at IS NULL`，不是"最新一条"，
  所以撤回留下的记录不会假装还在等审核
