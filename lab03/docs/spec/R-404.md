# R-404 未发货全额退款与恢复上架（REQ-016 前半）

## 行为实例

| # | 场景 | 预期 |
|---|---|---|
| 1 | 卖家发货前买家申请退款 | 订单「已退款」，退款单 1 条，商品「待付款锁定」→「已发布」，重新出现在搜索 |
| 2 | 预售订单（已进入交易中）退款 | 商品恢复「已预售」，不需要重新送审 |
| 3 | 未支付的订单申请退款 | 409「订单尚未支付，没有可退款项」 |
| 4 | 卖家替买家申请退款 | 403 且写 denied 日志（客服/管理员例外，持 `order.refund`） |
| 5 | 已发货后再申请 | 409（一期只支持未发货全额退款） |
| 6 | 预售订单退款 | `_has_paid` 认出定金/尾款流水挂在预约上，不误判为「未支付」 |

## 契约

- `trade/services.py::request_refund(order, *, actor, reason="", now=None) -> Order`
  - 允许的角色：买家本人（`order.refund_request`），或客服/管理员（`order.refund`）
  - 只允许「待发货」
  - `_has_paid(order)`：订单流水 → 若无，`source_reservation_id` 的预约流水
  - 成功后 `_restore_product(order)`：预售商品回「已预售」，普通商品回「已发布」
- 退款单落在 `trade.models.Refund(order=...)`，金额 = 订单应付金额
