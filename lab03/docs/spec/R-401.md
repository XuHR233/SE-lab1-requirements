# R-401 下单锁货（REQ-013）

## 行为实例

| # | 场景 | 预期 |
|---|---|---|
| 1 | 买家对已发布商品下单 | 201，订单「待付款」，`expires_at = now + 15 分钟`，商品「待付款锁定」且 `version + 1` |
| 2 | 同一买家重复提交（带旧版本） | 201，返回**原订单号**，库里仍 1 条订单 |
| 3 | 另一买家持旧版本下单 | 409「商品已被修改，请刷新后重试」 |
| 4 | 另一买家对已锁定商品下单 | 409「该商品已被锁定」 |
| 5 | 卖家买自己的商品 | 403 且写 denied 日志 |
| 6 | 游客下单 | 403 且写 denied 日志 |
| 7 | 预售商品直接下单 | 409「预售商品需先预约」 |
| 8 | **50 个买家并发下单** | 恰好 1 成功、49 个「该商品已被锁定」，订单 1 条，商品「待付款锁定」 |
| 9 | 15 分钟未支付 | `sweep()` 关闭为「已取消」，商品恢复「已发布」，可再次下单 |

## 契约

- `trade/services.py::create_order(product, *, buyer, request_key="", expected_version=None, now=None) -> Order`
  判定顺序（顺序本身是契约，见 原独立仓库历史材料（`docs/evidence/day4.md`，未随公开版迁移） §1-3）：
  1. 自购拒绝（REQ-001）
  2. `can(buyer, "order.create")`，失败写 denied 日志
  3. `product.is_presale` → 409
  4. **同买家已有待付款订单 → 返回原单**（锁货会让版本 +1，买家手里的对象必然过期）
  5. `expected_version` 不符 → 409
  6. 状态不是「已发布」→ 409
  7. 已有有效订单 → 409「该商品已被锁定」
  8. 条件 `UPDATE ... WHERE id=? AND status='已发布'`，`rowcount == 1` 才建单
- 幂等与唯一性双保险：应用层 `order.create` 日志 + 数据库部分唯一约束 `ux_order_active_per_product`
  （`status IN (待付款, 待发货, 待收货, 纠纷中)`）
- 事务边界：条件 UPDATE 与建单同一 `atomic()`；**冲突异常必须在事务外抛**，否则会把赢家的 UPDATE 一起回滚
