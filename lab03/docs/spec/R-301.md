# R-301 预约创建与唯一性（REQ-006 前半）

## 行为实例

| # | 场景 | 预期 |
|---|---|---|
| 1 | 买家对已预售商品发起预约 | 201，预约状态「待付定金」，定金窗口 15 分钟 |
| 2 | 对非预售商品发起预约 | 409 |
| 3 | 卖家预约自己的商品 | 403 且写 denied 日志（REQ-001） |
| 4 | 同一商品已有有效预约，另一买家来预约 | 409「该商品已有有效预约」 |
| 5 | 同一买家带同一 `request_key` 重复提交 | 201，返回**同一条**预约 |
| 6 | 带过期 `version` 提交 | 409「商品已被修改」 |
| 7 | 有效期 181 天 | 400 |
| 8 | 定金 + 尾款 ≠ 商品价格 | 400 |
| 9 | 两个连接同时插同一商品的有效预约 | 数据库部分唯一索引拒绝其中一条（`IntegrityError` 转 409） |
| 10 | 有有效预约期间，该商品对所有人从列表/搜索消失 | 游客、其他买家、管理员都查不到 |

## 契约

- `reservations/models.py::Reservation`，7 态：待付定金 / 待确认 / 待到货 / 待付尾款 / 已完成 / 已取消 / 已拒绝；
  `ACTIVE_STATUSES` = 前四态
- 部分唯一约束 `UniqueConstraint(fields=["product"], condition=Q(status__in=ACTIVE_STATUSES), name="ux_reservation_active_per_product")`
- `reservations/models.py::active_product_ids() -> set[int]`、`has_active(product) -> bool`，供 `catalog` 查询口径使用
- `reservations/services.py::reserve(product, *, buyer, request_key="", expected_version=None, now=None) -> Reservation`
- 有效期与金额口径：定金 > 0、尾款 > 0、定金 + 尾款 == 商品价格、有效期 1..180 天
