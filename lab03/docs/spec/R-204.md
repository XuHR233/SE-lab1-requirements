# R-204 下架与违规处置（REQ-008、REQ-009）

## 行为实例

| # | 操作 | 预期 |
|---|---|---|
| 1 | 卖家下架已发布商品 | 变已下架，从他人检索结果消失 |
| 2 | 已下架商品直接上架 | 不允许，必须先回草稿 |
| 3 | 已下架 → 草稿 → 重提 | 变待审核，需再审一次 |
| 4 | 管理员违规下架但不写理由 | 拒绝 |
| 5 | 普通用户执行违规下架 | 拒绝（无权） |
| 6 | 管理员违规下架已发布商品 | 变违规下架，记一条流水 |
| 7 | 已售出商品违规下架 | 拒绝（不在可处置范围） |
| 8 | 违规下架 → 草稿 | 允许，但再次上架仍要审核 |
| 9 | 卖家下架待付款锁定商品 | 拒绝（卖家没有这条转换） |
| 10 | 卖家下架交易中商品 | 拒绝（只能由客服或管理员裁定终止） |
| 11 | 客服裁定终止交易中商品 | 变已下架，记一条流水 |
| 12 | 普通用户裁定终止交易中商品 | 拒绝（无退款权） |
| 13 | 管理员违规下架交易中商品 | 拒绝（交易中不可违规下架） |
| 14 | 卖家下架已预售商品 | 变已下架（预售商品同样给卖家这条边） |

第 9–14 条是 2026-11-21 按实验二状态图（`lab02/UML/状态图.puml`、`状态图2_异常与退出.puml`）补的：
卖家自主下架只覆盖已发布/已预售；交易中只能走裁定终止；交易中不允许直接违规下架。

## 契约

- `catalog/services.py::unpublish(product, *, actor) -> Product`，只有已发布/已预售能下架
- `catalog/services.py::back_to_draft(product, *, actor) -> Product`
- `catalog/services.py::takedown(product, *, actor, reason) -> Product`，先查表再拒绝，拒绝时记日志
- **交易中→已下架（裁定终止）Day 2 不提供入口。** 第三轮复核实测：只查全局 `order.refund`
  权限就能用一个商品 id 把交易中商品变成已下架，等于伪造"裁定"。这条边留在
  `catalog/state.py::PRODUCT_TRANSITIONS` 里，由 M4 的订单与退款流程满足前置（订单属于该商品、
  协商/举证已核实、退款按 REQ-016 出结果）后调用 `transit(product, OFFSHELF)`
- 设计差异：方案里写的是 `relist()`，实现拆成 `back_to_draft()` + `submit_for_audit()` 两步，
  因为"已下架不能直接上架"本来就是 REQ-008 的要求，一个函数做不成两段审核
- 拒绝分两类：权限不足 → 403（`_deny()` 记日志），状态不允许 → 409（`_deny_transit()` 记日志）
