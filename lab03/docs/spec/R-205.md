# R-205 检索与可见性（REQ-003、REQ-011、REQ-012）

两套口径必须分开，混在一起就会把已售出商品漏到列表里：

| 口径 | 函数 | 谁能看到 |
|---|---|---|
| 列表 / 检索 | `listable()` | **与角色无关**：只有已发布与已预售；已售出永不出现 |
| 详情 | `visible_to(user)` | 游客只看已发布/已预售；卖家加自己的任意状态；客服与管理员看任意状态 |

## 行为实例

| # | 查询 | 预期 |
|---|---|---|
| 1 | 游客检索 | 只返回已发布与已预售 |
| 2 | 卖家本人检索 | **仍然只返回已发布与已预售**（自己的草稿不进列表） |
| 3 | 管理员、客服检索 | **仍然只返回已发布与已预售**（已售出谁都不出现在列表里） |
| 4 | 关键词"尼康 镜头" | 命中含"尼康"或"镜头"的商品（词间取或） |
| 5 | 关键词 + 分类 + 价格区间 | 三个条件取交 |
| 6 | 按价格升序 | 结果有序 |
| 7 | 价格下限 > 上限 | 400，不返回空列表混过去 |
| 8 | 页码越界 | 返回空列表，不报错 |
| 9 | 已售出商品 | 不出现在检索结果里（卖家、管理员、客服都一样） |
| 10 | 已售出商品的详情 | 卖家（本人）与客服/管理员能打开，游客与无关会员 404 |
| 11 | 别人的草稿详情 | 404，不当"无权限"泄露存在性 |

第 10 条的"对应订单买卖双方可凭订单进详情"要等 M4 订单表；目前按角色近似，
已在 `catalog/search.py` 的注释里写明这笔账留给 M4。

## 契约

- `listable() -> QuerySet[Product]`
- `visible_to(user) -> QuerySet[Product]`
- `search(*, keyword=None, category_id=None, tag=None, price_min=None, price_max=None, sort="newest", page=1) -> QuerySet`
  （**不再收 `user` 参数**：检索口径与角色无关，多传一个 user 只会让调用方以为结果跟着角色变）
- 排序白名单 `SORT_CHOICES`（newest / oldest / price_asc / price_desc），未知排序退回 newest
- 分页固定 `PAGE_SIZE = 12`，页码非法按第 1 页处理
- 关键词匹配范围：标题、品牌、描述、卖家用户名
